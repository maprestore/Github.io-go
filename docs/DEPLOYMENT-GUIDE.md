# LogiSwift — Complete Deployment Guide

This guide walks you through deploying every part of the LogiSwift stack:
- **Supabase** — cloud database (free tier)
- **Render** — backend API server (free tier)
- **GitHub Pages** — frontend hosting (free)
- **Formspree** — contact form emails (free tier)
- **Custom domain** — logiswift.delivery

Estimated setup time: **30–45 minutes**

---

## Overview of the Architecture

```
Browser → GitHub Pages (index.html / admin.html)
                ↓ API calls
         Render (server.js)
                ↓ database queries
         Supabase (PostgreSQL)
```

---

## PART 1 — Set Up Supabase (Database)

### 1.1 Create a Supabase account
1. Go to [https://supabase.com](https://supabase.com) and click **Start your project**
2. Sign up with GitHub or email
3. Click **New Project**
4. Fill in:
   - **Project name:** `logiswift`
   - **Database password:** Choose a strong password (save it — you won't need it directly but keep it)
   - **Region:** Choose the closest to your users
5. Click **Create new project** and wait ~2 minutes for it to spin up

### 1.2 Create the shipments table
1. In your Supabase dashboard, click **SQL Editor** in the left sidebar
2. Click **New query**
3. Paste the following SQL and click **Run**:

```sql
CREATE TABLE shipments (
  id              BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  "shipmentId"    TEXT NOT NULL UNIQUE,
  sender          TEXT NOT NULL,
  receiver        TEXT NOT NULL,
  weight          NUMERIC NOT NULL DEFAULT 0,
  status          TEXT NOT NULL DEFAULT 'Manifest Created',
  location        TEXT NOT NULL,
  eta             TEXT DEFAULT '',
  "imageUrl"      TEXT DEFAULT '',
  notes           TEXT DEFAULT '',
  created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Allow public read access (for tracking on the homepage)
ALTER TABLE shipments ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Public can read shipments"
  ON shipments FOR SELECT
  USING (true);

CREATE POLICY "Service role has full access"
  ON shipments FOR ALL
  USING (true);
```

4. Verify the table was created by clicking **Table Editor** in the sidebar — you should see `shipments` listed.

### 1.3 Get your Supabase credentials
1. Go to **Project Settings** (gear icon, bottom of left sidebar)
2. Click **API**
3. Copy and save these two values — you will need them in Part 2:
   - **Project URL** (looks like `https://xyzxyz.supabase.co`) → this is your `SUPABASE_URL`
   - **anon / public key** (long string starting with `eyJ...`) → this is your `SUPABASE_ANON_KEY`

## PART 2 — Deploy the Backend to Render

### 2.1 Push your code to GitHub
If your project is not already in a GitHub repo:
1. Go to [https://github.com](https://github.com) → **New repository**
2. Name it `logiswift-backend` (or any name)
3. Keep it **Private** (recommended — your server code is here)
4. Upload these files:
   - `server.js`
   - `package.json`

Or from your terminal:
```bash
git init
git add server.js package.json
git commit -m "Initial deploy"
git remote add origin https://github.com/YOUR_USERNAME/logiswift-backend.git
git push -u origin main
```

### 2.2 Create a Render account
1. Go to [https://render.com](https://render.com)
2. Sign up with your GitHub account (recommended — makes deployment easier)

### 2.3 Create a new Web Service on Render
1. Click **New +** → **Web Service**
2. Connect your GitHub account if prompted
3. Select your `logiswift-backend` repository
4. Configure the service:
   - **Name:** `logiswift-api`
   - **Region:** Choose closest to your users
   - **Branch:** `main`
   - **Runtime:** `Node`
   - **Build Command:** `npm install`
   - **Start Command:** `node server.js`
   - **Instance Type:** `Free`

### 2.4 Set environment variables on Render
Before clicking Deploy, scroll down to **Environment Variables** and add:

| Key | Value |
|-----|-------|
| `ADMIN_KEY` | Your chosen admin password (e.g., `MySecurePass2026!`) |
| `SUPABASE_URL` | Your Supabase Project URL from Part 1.3 |
| `SUPABASE_ANON_KEY` | Your Supabase anon key from Part 1.3 |

> **Important:** Never use a simple password for `ADMIN_KEY`. Use at least 12 characters with letters, numbers, and symbols.

### 2.5 Deploy
1. Click **Create Web Service**
2. Render will build and deploy automatically (~3–5 minutes)
3. When complete, you'll see a URL like: `https://logiswift-api.onrender.com`
4. Test it by visiting `https://logiswift-api.onrender.com/api/health` — you should see:
   ```json
   { "status": "online", "db": "connected" }
   ```

### 2.6 Note your Render URL
Copy your Render URL (e.g., `https://logiswift-api.onrender.com`). You'll need it in the next part.

> **Free tier note:** Render's free tier spins down after 15 minutes of inactivity. The first request after sleep takes 30–60 seconds. This is expected behaviour — upgrade to a paid plan to keep it always-on.

## PART 3 — Update the Frontend with Your Render URL

Before uploading to GitHub Pages, you need to update the API URL in both HTML files.

### 3.1 Update every frontend file
Each of `index.html`, `about.html`, `tracking.html`, and `admin.html` has this line near the top of its `<script>` block:

```javascript
const API_BASE = "https://github-io-go.onrender.com/api";
```

Change it in **all four files** to your actual Render URL (note `about.html` doesn't call the API directly today, but keep it consistent in case you extend it):

```javascript
const API_BASE = "https://YOUR-APP-NAME.onrender.com/api";
```

`index.html`, `tracking.html`, and `admin.html` all use the exact same `API_BASE` value, already including the trailing `/api`.

## PART 4 — Deploy the Frontend to GitHub Pages

### 4.1 Create a GitHub Pages repository
1. Go to GitHub → **New repository**
2. **Repository name must be exactly:** `YOUR_USERNAME.github.io` (for a root domain site)
   - OR any name like `logiswift-site` (for a path like `your_username.github.io/logiswift-site`)
3. Set visibility to **Public** (required for GitHub Pages on free plan)

### 4.2 Upload the frontend files
Upload these files to the repository:
- `index.html`
- `about.html`
- `tracking.html`
- `admin.html`
- `CNAME` (only if you are using a custom domain — see Part 5)

### 4.3 Enable GitHub Pages
1. Go to your repository → **Settings** → **Pages**
2. Under **Source**, select:
   - **Branch:** `main`
   - **Folder:** `/ (root)`
3. Click **Save**
4. After ~1 minute, your site will be live at:
   `https://YOUR_USERNAME.github.io/REPO_NAME/`

## PART 5 — Set Up Your Custom Domain (logiswift.delivery)

Skip this section if you don't have a custom domain yet.

### 5.1 Configure GitHub Pages for custom domain
1. In your GitHub repo → **Settings** → **Pages**
2. Under **Custom domain**, enter: `logiswift.delivery`
3. Click **Save**
4. GitHub will create a `CNAME` file in your repo automatically (or use the one in the zip)

### 5.2 Configure DNS at your domain registrar
Log in to wherever you bought `logiswift.delivery` and add these DNS records:

**Option A — Root domain (logiswift.delivery):**

| Type | Host | Value |
|------|------|-------|
| `A` | `@` | `185.199.108.153` |
| `A` | `@` | `185.199.109.153` |
| `A` | `@` | `185.199.110.153` |
| `A` | `@` | `185.199.111.153` |
| `CNAME` | `www` | `YOUR_USERNAME.github.io` |

**Option B — Subdomain only (www.logiswift.delivery):**

| Type | Host | Value |
|------|------|-------|
| `CNAME` | `www` | `YOUR_USERNAME.github.io` |

### 5.3 Enable HTTPS
1. Back in GitHub Pages settings, wait 10–30 minutes for DNS to propagate
2. Once the custom domain shows **DNS check successful**, tick **Enforce HTTPS**
3. Your site is now live at `https://logiswift.delivery`

### 5.4 CORS is already handled
`server.js` already allows `https://logiswift.delivery` and `https://www.logiswift.delivery` in its `ALLOWED_ORIGINS` list, along with any `*.github.io`, `*.onrender.com`, and `localhost` origin — no environment variable or Render setting is needed for the domain in this template.

If you rebrand to a different domain, edit the `ALLOWED_ORIGINS` array directly in `server.js` (Part 2.1) and redeploy.

## PART 6 — Set Up Formspree (Contact Form Emails)

### 6.1 Create a Formspree account
1. Go to [https://formspree.io](https://formspree.io)
2. Sign up with your email
3. Click **New Form**
4. Give it a name: `LogiSwift Contact`
5. Set the email to receive submissions
6. Copy your **Form ID** (8-character code, e.g., `xpwznbqr`)

### 6.2 Update index.html
Find this line in `index.html`:
```html
<form id="contact-form" action="https://formspree.io/f/YOUR_FORMSPREE_ID_HERE"
```

Replace `YOUR_FORMSPREE_ID_HERE` with your actual form ID:
```html
<form id="contact-form" action="https://formspree.io/f/xpwznbqr"
```

### 6.3 Re-upload index.html to GitHub
Commit and push the updated `index.html` — GitHub Pages will update within ~1 minute.

## PART 7 — Set Your Admin Password

The admin password you set as `ADMIN_KEY` on Render is what you enter on the `admin.html` login screen.

To access the admin console:
1. Visit `https://logiswift.delivery/admin.html`
2. Enter your `ADMIN_KEY` value
3. You're in — the session lasts 30 minutes and automatically expires

To change the password:
1. Go to Render → your service → **Environment**
2. Update the `ADMIN_KEY` value
3. Click **Save Changes** — Render will redeploy automatically

Run through this checklist after deployment:

- [ ] Visit `https://logiswift.delivery` — homepage loads correctly
- [ ] Visit `https://YOUR-APP.onrender.com/api/health` — returns `{ "status": "online", "db": "connected" }`

- [ ] Send a test message via the contact form

- [ ] Print a waybill from one of the shipment rows — print dialog opens

## Troubleshooting

### "Database not configured" error
→ Your `SUPABASE_URL` or `SUPABASE_ANON_KEY` is not set correctly on Render. Double-check for typos and spaces.

### Admin login always fails
→ Check that `ADMIN_KEY` is set on Render. Visit `/api/health` to confirm the server is running. Make sure you're typing the password exactly (case-sensitive).

### Render server takes 30–60 seconds to respond
→ This is normal on the free tier. The server sleeps after 15 minutes of no requests. Upgrade to a Starter plan ($7/month) for always-on hosting.

### Contact form shows "not configured" message
→ You haven't replaced `YOUR_FORMSPREE_ID_HERE` in `index.html`. Follow Part 6.

### Custom domain not working
→ DNS changes take up to 48 hours to propagate. Use [https://dnschecker.org](https://dnschecker.org) to verify your records are live.

### Tracking works in admin but not on homepage
→ Check that `API_BASE` in `index.html` ends with `/api` (e.g., `https://your-app.onrender.com/api`). `admin.html` and `tracking.html` use the exact same base — make sure all three were updated together.

### CORS errors in the browser console
→ Make sure your domain is listed in the `server.js` CORS allowed origins. If you added a new domain, update the `ALLOWED_ORIGINS` array in `server.js` and redeploy.
